About

The part I care about is where design meets engineering.

An interface is working when it stops feeling like software and starts feeling obvious — when the next tap is where you already expected it to be. Most of that is unglamorous: naming things well, keeping state somewhere sensible, and deleting the screen nobody needed.

On mobile that usually means Flutter — one codebase that still feels native on both platforms, with Riverpod holding state and go_router handling navigation. On the web it is Next.js and TypeScript, reaching for Redux Toolkit only when the state genuinely earns it. Behind both, Java and Spring.

I write tests, I read other people's code slowly, and I would rather ship something small that works than something large that mostly does.
